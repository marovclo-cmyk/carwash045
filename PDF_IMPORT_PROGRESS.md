# Импорт PDF-отчёта «Касса» в архив — прогресс

## Задача
Пользователь хочет отправлять боту PDF (свой же отчёт «Касса», который бот генерирует по `/pdf`),
и бот должен распознать его и записать данные обратно в архив (`carwash_archive.json`) —
чтобы отчёты, статистика и «кто сколько заработал» продолжали работать, если архив потерялся
или день нужно восстановить из старого файла.

Подтверждено с пользователем: PDF — **свой же формат** (генерируется `pdf_generator.py`), не произвольный.

## Формат PDF (для справки, как он устроен — см. pdf_generator.py)
- Шапка-таблица: Дата / Сотрудники+Итого / Дневная выручка / (Лояльность, если есть) /
  Наличка+Безнал+Visa / Зарплата (все мойщики + админ последним) / Расходы / (Доходы, если есть) / Остаток
- Таблица машин: строка-заголовок `#`, потом блоки по сотрудникам:
  синяя строка с именем → строки машин (`#, марка/клиент, услуга, цена, оплата`) →
  зелёная строка "Итог {emp}: намыл X руб. → зарплата (30%) = Y руб."
- Блок товаров (если есть): синяя строка "Товары (итого N руб.)" → строки товаров
- Пустые строки-заполнители до 21 строки
- При переполнении страницы — новая страница, шапка таблицы машин повторяется, но
  шапка со сводкой (Дата/Зарплата/Расходы/...) НЕ повторяется — она только на 1-й странице

Проверено через `pdfplumber.extract_tables(vertical_strategy=lines, horizontal_strategy=lines)`
на синтетическом PDF — таблица извлекается чисто, колонки предсказуемо ложатся в индексы
[0]=#, [1]=машина/текст, [3]=услуга, [5]=цена, [7]=оплата (индексы 2,4,6 — всегда None, артефакт
внутренних vline).

## Ключевое архитектурное решение — как восстановить зарплату точно
В PDF НЕТ `service_keys` (только текстовая метка услуги), поэтому нельзя надёжно
пересчитать % мойщика по `config.SERVICES`. Решение: не пересчитывать проценты вообще —
- каждой восстановленной машине ставим `price_breakdown = {"_imported": {price: <цена>, percent: 0, name: <текст услуги из PDF>}}`
  → её вклад в зарплату мойщика через процент = 0
- зарплату мойщика берём НАПРЯМУЮ из зелёной строки "Итог {emp}: намыл X → зарплата (30%) = Y"
  и кладём в `session["fixed_rates"][emp] = Y` (fixed_rates прибавляется поверх процента,
  а процент = 0 → итог точно = Y, как в оригинальном PDF)
- для админа аналогично: `admin_percent = 0`, `admin_fixed_rate = <сумма админа из строки "Зарплата:">`
  (админ там всегда последний в списке — так его добавляет pdf_generator.py)
- `washer_totals`/"намыл" при этом всё равно считается верно, т.к. это просто сумма `car["price"]`,
  а цены машин мы переносим из PDF как есть

Известное ограничение: скидки лояльности (`loyalty`) в PDF указаны только общей суммой
(строка "Лояльность: N руб."), без привязки к конкретной машине/способу оплаты.
При восстановлении сумма лояльности целиком привязывается к первой машине с оплатой "нал"
(или к первой машине вообще, если нала нет) — это лучшее приближение, которое возможно
без потери итоговых цифр (grand_total). Если у исходного дня было несколько разных скидок
на разные способы оплаты — разбивка Наличка/Visa/Безнал после восстановления может немного
отличаться от оригинала (сама выручка и зарплаты — нет). Пользователь будет предупреждён об
этом в сообщении-подтверждении, если в PDF обнаружена лояльность.

# Доп. функция: PDF-ведомость выдачи премии (недельная зарплата)

**Дата:** 07.08.2026

Пользователь прислал фото бумажного бланка «Ведомость выдачи премии в сети
автомоек Формула» (Сотрудник × ПН..ВС × ИТОГО, подпись «Ответственный за
выдачу»). Задача: бот должен уметь генерировать PDF в ТОЧНО таком же виде,
но уже заполненный реальными данными за неделю — по той же логике, что и
обычный отчёт «Касса», только сводка не по машинам дня, а по зарплате
сотрудника за каждый день недели.

## Реализация
- `pdf_generator.py` → `generate_salary_sheet_pdf(branch, week_start, week_end,
  employees, admin_name, output_path)` — рисует бланк тем же стилем/шрифтами/
  палитрой, что и обычный отчёт «Касса» (тёмно-синяя шапка таблицы, серая
  зебра строк). Источник данных по сотруднику за каждый день — уже готовая
  функция `employee_stats.all_employees_period_stats()` (она и так умеет
  агрегировать заработок по ролям — мойщик/администратор — в одну карточку
  сотрудника), просто распределяем `emp["days"]` по колонкам ПН..ВС через
  `datetime.weekday()`. Никакой новой бизнес-логики подсчёта зарплаты не
  писалось — переиспользована та же, что использует `/week`.
- `handlers/reports.py` → команда `/premium`:
  - без аргументов — текущая календарная неделя (Пн–сегодня), как и `/week`;
  - `/premium last` — прошлая полная неделя (Пн–Вс);
  - доступна только owner/admin филиала (как остальные отчёты).
- Зарегистрирована в `bot.py`.
- «Ответственный за выдачу» — имя администратора филиала
  (`sessions.get_branch_admin_name`), как в исходном бланке.

## Тестирование
Собран тестовый архив на 3 дня недели (Пн/Ср/Пт) с двумя мойщиками и
администратором → `all_employees_period_stats` → `generate_salary_sheet_pdf`
→ извлечено через `pdfplumber` и сверено построчно: суммы по дням и ИТОГО
совпали с ожидаемыми на 100%. Также отрендерил страницу в PNG и визуально
сверил с фото бланка — расположение колонок и заголовок идентичны.
