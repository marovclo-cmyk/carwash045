Источник: `main-page-concept.html`, присланный пользователем как эталон

Работа ведётся ПОЭТАПНО (см. чек-лист в конце файла). Этот файл — общий

## 1. Где живут токены

- **Сайт**: `webapp/static/site-theme.css` — подключается один раз через
  `site-common.js` на все страницы сайта (кроме `site-login.html`, где
  подключён напрямую `<link>`).
- **Mini App**: `webapp/static/index.html` — свой инлайн `<style>` (SPA не
  грузит `site-theme.css` отдельно), поэтому те же токены и классы
  продублированы внутри файла. При изменении палитры/компонентов — менять
  синхронно в обоих местах.

## 2. Палитра (токены)

| Переменная | Значение (тёмная тема) | Назначение |
|---|---|---|
| `--bg` | `#08080B` | фон приложения/сайта |
| `--surface-0..3` | `#0F1116 → #262832` | непрозрачные поверхности (сайдбар, инпуты) — используются там, где glass-эффект не нужен |
| `--text` / `--text-secondary` / `--text-muted` | `#F5F6FA` / `#9096A3` / `#5E6270` | текст (старые имена, используются в уже написанных экранах) |

| `--accent` / `--accent-b` | `#6A8BFF` / `#A24BFF` | основной градиент (кнопки, активные состояния, hero) |
| `--good` / `--green` | `#34D399` | успех/оплачено |
| `--orange` | `#FFB648` | предупреждение/в работе |
| `--red` | `#FF6B8B` | ошибка/удаление |
| `--glow-a/b/c` | `#3B6BFF` / `#A24BFF` / `#FF4FA3` | цвета фоновых «орбов» и hero-градиента |
| `--glass` / `--glass-hover` / `--glass-border` | `rgba(255,255,255,.055/.09/.09)` | фон/бордер стеклянных карточек |

Радиусы: `--radius-sm:12px`, `--radius-md:16px`, `--radius-lg:22px`,
`--radius-xl:30px`. Блюр: `--blur-glass:20px`, `--blur-nav:28px`.

Светлая тема (`html[data-theme="light"]`) использует те же имена
переменных с адаптированными значениями (glass — тёмный полупрозрачный на
светлом фоне, а не белый).

Старые переменные (`--surface-*`, `--accent-tint`, `--purple-tint` и т.п.)
**сохранены** — их использует весь уже написанный HTML/JS. Новые токены
добавлены рядом, ничего не переименовано и не удалено, чтобы не сломать
страницы до того, как до них дойдёт очередь по плану.

## 3. Переиспользуемые компоненты (одинаковые классы на сайте и в аппе)

- **`.orb-bg` + `.orb.orb-a/.orb-b/.orb-c`** — фиксированный слой из 3
  размытых цветных пятен (`filter:blur(90px)`), плавно двигающихся
  (`@keyframes orb-float-1/2`). Добавляется один раз в разметку страницы,
  `pointer-events:none`, не мешает контенту.
- **`.glass-card`** — базовая полупрозрачная карточка с блюром фона
  (`backdrop-filter`). Строительный блок для списков, статов, секций.
- **`.hero-card`** — крупная карточка с анимированным цветным градиентом
  (`@keyframes hero-shift`) для главных сумм/итогов (выручка за смену,
  баланс).
- **`.pill.ok` / `.pill.wip`** — статус-бейджи (оплачено / в работе).
- **`.action-tile`** + `.sq.b1..b4` — квадратные плитки быстрых действий
  с цветными градиентными иконками.
- **`.glass-navbar`** — плавающий полупрозрачный нижний навбар (мобильный).

## 6. Известные ограничения / технический долг

- Каждая из 10 HTML-страниц сайта содержит устаревшую инлайн-копию каркаса
  (`:root` со старыми iOS-цветами `#007AFF`/`#0A0A0B` и т.д., дублирующиеся
  `.sidebar`/`.panel`/`.btn`). Она **не влияет на итоговый вид** (см. Этап
  5 — перебивается `site-theme.css` через порядок подключения), но
  формально это дублирование кода. Полная чистка (вынос общего каркаса в
  один файл, удаление дублей из всех 10 файлов) — отдельная задача по
  рефакторингу, не требуется для визуального результата этого ТЗ.
  **УТОЧНЕНИЕ (12.08.2026, этап «Единый app shell + навигация»):** этот
  пункт устарел применительно к САМОМУ САЙДБАРУ/НАВИГАЦИИ (не ко всему
  инлайн-каркасу в целом, который сам по себе безвреден и описан выше) —
  на момент аудита сайдбар/навигация уже давно вынесены в единый источник
  правды: массив `NAV` + функция `CW.renderSidebar()` в `site-common.js`,
  инжектируемые в пустой `<div class="rail" id="sidebarRoot">` на каждой
  из 12 авторизованных страниц (проверено построчно — все 12 вызывают
  `CW.renderSidebar("<свой-key>")` с правильным activeKey, дублирования
  разметки сайдбара НЕТ ни в одном файле). Единственный реальный пробел,
  найденный при аудите, был не в дублировании, а в ПОЛНОМ ОТСУТСТВИИ
  навигации на узких экранах: `.rail{display:none}` ниже 980px ничем не
  заменялся — сайт был ненавигируем на телефоне/планшете. Закрыто этим же
  этапом, см. раздел «Мобильная навигация» ниже.

### Этап 5 — детали (Сайт: страницы по одной)

Важная находка: каждая из 10 страниц сайта хранит собственную инлайн-копию
общего каркаса (`:root`, `.sidebar`, `.panel`, `.stat-card`, `.btn` и т.д.) —
устаревшее легаси ещё с ранних версий проекта. Но `site-common.js`
подключает `site-theme.css` через `document.head.appendChild(...)`, что
физически помещает этот `<link>` **после** инлайн-`<style>` каждой
страницы. При равной специфичности побеждает последнее по порядку
правило — то есть `site-theme.css` **уже перекрывал** все инлайн-копии на
всех 10 страницах начиная с Этапа 4, просто это не было явно
задокументировано. Проверено сравнением (`diff`) стилей всех страниц:
структура идентична, отличаются только значения (палитра, отступы),
которые не участвуют в рендере, потому что переопределены.

Из-за этого страницы сайта уже выглядели в стиле «Glass/Orb» сразу после
Этапа 4. Этап 5 добавил точечные глобальные переопределения в
`site-theme.css` (используют `!important` там, где нужно перебить
инлайн-правило с точно такой же специфичностью и структурой селектора) —
они автоматически применились сразу ко всем страницам, которые содержат
эти компоненты:

- **`.pay-tag`** (способ оплаты — Dashboard/Касса/Финансы/История):
  прямоугольный бейдж → пилюля (`border-radius:100px`), как `.pill` в
  дизайн-концепте.
- **`table.data`** (таблицы операций — Dashboard/Финансы/История/Отчёты):
  hover-строка — `--glass-hover` вместо сплошного `--surface-2`; границы
  ячеек — `--glass-border`.
- **`.tag`** (статусы — Мойщики/Филиалы): пилюля вместо прямоугольника.
- **`.tabs`/`.tab`** (переключатель периода — Отчёты): glass-таблетка,
  активный сегмент — акцентный градиент (как `.segmented`/`.seg` в
  mini-app).
- **`.branch-card`** (карточки филиала — Филиалы/Отчёты): glass + блюр.
- Добавлен токен `--accent-gradient` в `site-theme.css` (уже был в
  `index.html`) для переиспользования в `.tab.active` и будущих правках.

Не тронуто в этом этапе намеренно: мелкие внутренние элементы форм
(`.svc-item`, `.csf-row`, `.split-row`, `.field`, `.list-row` и т.д.) —
это строки/чипы **внутри** уже стеклянных `.panel`/`.card`, их сплошной
слегка затемнённый фон обеспечивает читаемость поверх блюра (аналог
`.action-tile .sq` в концепте — сплошной элемент поверх стекла). Полная

### Этап 6 — финальная проверка (готово)

Найдено и исправлено (реальные баги, не косметика):

   записи, дропдаун поиска клиента и список кастомных услуг. Добавлена
   `escapeHtml()` и применена во всех местах, где в разметку попадает
   текст, введённый человеком.
3. Неопределённый CSS-класс `.section-label` — использовался в блоке
   постоянной скидки, но нигде не был объявлен ни в теме, ни в самом
   файле — текст оставался без стиля. Добавлено объявление (см. выше).
4. Удалён мёртвый CSS-класс `.modal-sub-note`, оставшийся от Этапа 4.

### Что сделано

Единый слой мобильной навигации — гамбургер-топбар вверху + выезжающий
слева drawer, оба показываются только через `@media(max-width:980px)`.
Реализовано ОДНИМ изменением в `site-common.js` (новые функции
`ensureMobileNavEl()`/`renderMobileNav()`, вызываются из конца уже
существующей `renderSidebar()`) — все 12 страниц сайта получили
мобильную навигацию автоматически, без правки самих HTML-файлов
(тот же принцип единого источника правды, что и у `NAV`/десктопного
сайдбара: один список пунктов меню, не два).

- **`.mobile-topbar`** — фиксированная полоса сверху (кнопка-гамбургер +
  логотип), видна только ≤980px.
- **`.mobile-nav-backdrop` + `.mobile-nav-drawer`** — затемнение + панель
  280px, выезжает слева (`transform: translateX`), содержит те же
  сгруппированные пункты меню, что и десктопный `.rail` (тот же `NAV`,
  та же фильтрация по роли `ownerOnly`/`adminOnly`, тот же активный
  пункт), плюс филиал (с 12.08.2026, этап 2 — переключаемый для роли
  «владелец», см. ниже) и блок пользователь/выход.
- Стилистика продолжает язык `.rail`/`.rail-item` (тёмный фон,
  оранжевый градиент активного пункта) — не новый визуальный язык.
- `body.mobile-nav-locked` — блокирует скролл фона, пока drawer открыт.

### Этап 2 (12.08.2026) — смена филиала из мобильного drawer

Закрывает первый из двух пунктов «Не сделано» этапа 1 (ниже). Владелец —
единственная роль, у которой филиал вообще переключаем (админ/мойщик

### Этап 3 (12.08.2026) — мини-календарь в мобильном drawer

Закрывает второй (последний) из двух пунктов «Не сделано» этапа 1.
`buildCalendarHtml()` — прежде единственный вызывающий (`renderSidebar`
для раскрытого десктопного сайдбара) — стал параметризуемым по префиксу
id (`buildCalendarHtml(idPrefix)`, десктоп по-прежнему вызывает без
аргумента → те же id `railCal`/`calPrevM`/`calNextM`, что и раньше, без
изменения поведения). Причина префикса: десктопный `.rail` и мобильный
drawer оба присутствуют в DOM одновременно (десктопный вариант скрыт
только через CSS `@media`, не удалён из разметки) — без префикса
`document.getElementById("calPrevM")` в мобильном коде находил бы
десктопный элемент. Мобильный вызов — `buildCalendarHtml("mobile")`.

В отличие от десктопа, где календарь виден только при раскрытом (233px)
сайдбаре — переключатель, специфичный для *ширины* рейла, drawer в
мобильной версии всегда одной ширины, так что календарь сделан отдельным
раскрывающимся аккордеоном (`.mobile-nav-cal-toggle` + `.mobile-nav-cal-wrap`),
состояние открыт/закрыт запоминается в `localStorage` (`cw_mobile_cal_open`)
по тому же паттерну, что и `cw_rail_expanded` у десктопа — но это два
независимых переключателя, не связанных друг с другом.

Клик по дню / стрелки месяца используют тот же `calSelectCallback`/
`calViewDate`/`getCalDate()`/`setCalDate()`, что и десктопный календарь —
второго набора состояния календаря не появилось. На `booking.html`,
где зарегистрирован `CW.onCalDateSelect`, выбор дня в мобильном drawer
обновляет журнал без перезагрузки страницы (как и на десктопе); на
остальных страницах — переход на `/static/booking.html?date=...`.

**Затронутые файлы (этап 3):** `webapp/static/site-common.js`
(`buildCalendarHtml()` — добавлен параметр `idPrefix`; `renderMobileNav()`
— новый блок календаря-аккордеона), `webapp/static/css/theme-plata.css`
(`.mobile-nav-cal-toggle`, `.mobile-nav-cal-wrap` + переиспользование
уже существующих `.rail-cal*`/`.cal-cell*` — тот же тёмный визуальный
язык, без новой палитры).
